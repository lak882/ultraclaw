# Complex Record Map authoring reference

Complex Record Maps describe structured files that contain multiple record types, optionally preceded by a header and followed by a trailer. They compose existing `EnsLib.RecordMap.RecordMap` classes (one per record type) into a hierarchical structure and generate a single batch target class that carries all the parsed records together.

## File structure contract

A Complex Record Map file has three optional zones:

1. **Header record** (optional, non-repeating) — a single record at the top, identified by its leading data.
2. **Body** — a sequence of records and nested sub-sequences. Can repeat.
3. **Trailer record** (optional, non-repeating) — a single record at the bottom.

Every sequence must contain at least one record or sequence. Header and trailer records cannot repeat. If the entire body repeats (common for batched patient files), wrap it in a top-level `<RecordSequence repeating="1">`.

## Class structure

A ComplexMap compiles into two classes:

| Class | Role |
|-------|------|
| Your `Pkg.Foo.ComplexMap` (extends `EnsLib.RecordMap.ComplexMap`) | Holds the XData schema and the parser/writer. You author this. |
| Your `Pkg.Foo.ComplexMapBatch` (extends `EnsLib.RecordMap.ComplexBatch` and `Ens.Request`) | The generated message class. Properties map to each top-level record reference and sequence. Callers (BPs, DTLs, routing rules) work with this class. |

The batch class is generated by `EnsLib.RecordMap.ComplexGenerator.Generate()`, not by `$System.OBJ.Compile`. Compiling the ComplexMap alone will not produce the batch class.

## Parameters on the ComplexMap class

| Parameter | Value | Purpose |
|---|---|---|
| `BATCHCLASS` | Fully qualified batch class name | Distinct from the ComplexMap class; typically `<ComplexMapName>Batch`. |
| `RECORDMAPGENERATED` | `1` | Signals to the framework that the batch target class is auto-managed. If `0`, the batch class is hand-authored and generation skips it. |

## XData schema

The `XData ComplexBatch` block carries an XML document in the namespace `http://www.intersystems.com/Ensemble/RecordMap`. Root element is `<ComplexBatch>`.

### `<ComplexBatch>` attributes

| Attribute | Required | Value |
|---|---|---|
| `xmlns` | yes | `http://www.intersystems.com/Ensemble/RecordMap` |
| `name` | yes | Full class name of the ComplexMap itself |
| `char_encoding` | yes | Character encoding: `UTF-8`, `Latin1`, `Ascii`, etc. Overrides each referenced RecordMap's encoding |
| `targetClassname` | yes | Must equal the `BATCHCLASS` parameter value |
| `recordTerminator` | no | Line terminator, usually `\x0d\x0a` (CRLF) or `\x0a` (LF). Defaults to the platform default. |

### `<RecordReference>`

One record, identified by a referenced RecordMap class's `LeadingData`.

```xml
<RecordReference name="Patient" required="1" repeating="0"
                 recordMap="Pkg.RecordMap.Patient">
</RecordReference>
```

| Attribute | Value |
|---|---|
| `name` | Property name on the generated batch/sequence class |
| `required` | `0` or `1`. If `1`, the file must contain a matching record. |
| `repeating` | `0` or `1`. If `1`, the property is an array. |
| `recordMap` | Full class name of the referenced `EnsLib.RecordMap.RecordMap` |
| `minOccurs` / `maxOccurs` | Optional. Min/max repeats when `repeating="1"`. |

### `<RecordSequence>`

A named group containing records and other sequences. Treated as one composite object.

```xml
<RecordSequence name="Encounters" required="0" repeating="1">
  <RecordReference name="Encounter" required="1" repeating="0"
                   recordMap="Pkg.RecordMap.Encounter"/>
  <RecordReference name="EncounterLocation" required="0" repeating="1"
                   recordMap="Pkg.RecordMap.EncounterLocation"/>
</RecordSequence>
```

A sequence generates a helper class extending `EnsLib.RecordMap.ComplexSequence`. Each nested `<RecordReference>` or `<RecordSequence>` becomes a property on that helper.

### `<Header>` and `<Trailer>`

Top-level-only, non-repeating. Each contains exactly one `<RecordReference>`:

```xml
<Header>
  <RecordReference name="FileHeader" required="1" repeating="0"
                   recordMap="Pkg.RecordMap.FileHeader"/>
</Header>
<Trailer>
  <RecordReference name="FileTrailer" required="1" repeating="0"
                   recordMap="Pkg.RecordMap.FileTrailer"/>
</Trailer>
```

## Prerequisites on the referenced RecordMaps

Each `RecordMap` referenced by a ComplexMap must set:

1. `Parameter RecordInComplexMap = 1` on the RecordMap class.
2. `LeadingData="TAG|"` on its `<Record>` element, with the literal leading-data prefix that identifies this record type in the file. Example: `LeadingData="PAT|"` for patient records that start with `PAT|`.

Without these, the ComplexMap parser cannot route records to the right sub-RecordMap and will either fail parsing or silently drop records.

## Generation workflow

After every meaningful change to the ComplexMap (structural edit, new `<RecordReference>`, rename, etc.), regenerate the batch:

```
exec: Set sc = ##class(EnsLib.RecordMap.ComplexGenerator).Generate("Pkg.Foo.ComplexMap") Set %result = $System.Status.GetErrorText(sc)
```

This:

1. Parses the `XData ComplexBatch` block.
2. Creates or updates the batch class named by `BATCHCLASS`.
3. Creates helper sequence classes for each `<RecordSequence>`.
4. Wires properties on the batch class, one per top-level child of `<ComplexBatch>`.

If generation succeeds but the batch class has zero usable properties, verify the `targetClassname` on `<ComplexBatch>` matches the `BATCHCLASS` parameter exactly.

## Using in a production

### Inbound service (read files)

```xml
<Item Name="MPIFileService" Category="Inbound"
      ClassName="EnsLib.RecordMap.ComplexMap.FileService"
      PoolSize="1" Enabled="true">
  <Setting Target="Adapter" Name="FilePath">/data/mpi/in/</Setting>
  <Setting Target="Adapter" Name="FileSpec">*.dat</Setting>
  <Setting Target="Adapter" Name="ArchivePath">/data/mpi/archive/</Setting>
  <Setting Target="Host" Name="ComplexMap">Pkg.Foo.ComplexMap</Setting>
  <Setting Target="Host" Name="TargetConfigNames">MPIProcessor</Setting>
</Item>
```

The service sends a single message of type `Pkg.Foo.ComplexMapBatch` per file.

### Outbound operation (write files)

```xml
<Item Name="MPIFileWriter" Category="Outbound"
      ClassName="EnsLib.RecordMap.ComplexMap.FileOperation"
      PoolSize="1" Enabled="true">
  <Setting Target="Adapter" Name="FilePath">/data/mpi/out/</Setting>
  <Setting Target="Host" Name="ComplexMap">Pkg.Foo.ComplexMap</Setting>
  <Setting Target="Host" Name="Filename">%Q.dat</Setting>
</Item>
```

The operation accepts a `Pkg.Foo.ComplexMapBatch` message and writes it back out using the ComplexMap's structure as a template.

## Real-world example: hybrid-hierarchy MPI file

This is a ComplexMap from a clinical master-patient-index POC. The file contains, per patient: demographics + related person-level data (addresses, contacts, coverage, providers) flat at the top; Encounter sub-groups; Appointment sub-groups; Survey sub-groups; and flat clinical entities (allergies, diagnoses, labs, vitals, meds, procedures, immunizations, problems, social history) interleaved with the grouped data.

```objectscript
/// Hybrid structure ComplexMap - Clinical entities flat at top level,
/// Encounter/Appointment/Survey children nested.
/// Eliminates k2 index collision for clinical data while keeping
/// encounter structure.
Class Pkg.POC.RecordMap.ComplexMap.MasterPatientRecordMap Extends EnsLib.RecordMap.ComplexMap
{

Parameter BATCHCLASS = "Pkg.POC.RecordMap.ComplexMap.MasterPatientRecordMapBatch";
Parameter RECORDMAPGENERATED = 1;

XData ComplexBatch [ XMLNamespace = "http://www.intersystems.com/Ensemble/RecordMap" ]
{
<ComplexBatch xmlns="http://www.intersystems.com/Ensemble/RecordMap"
              name="Pkg.POC.RecordMap.ComplexMap.MasterPatientRecordMap"
              char_encoding="UTF-8"
              targetClassname="Pkg.POC.RecordMap.ComplexMap.MasterPatientRecordMapBatch">

  <!-- Patient group: one Demographic, then any number of person-level sub-records. -->
  <RecordSequence name="Patient" required="1" repeating="0">
    <RecordReference name="Demographic"    required="1" repeating="0" recordMap="Pkg.POC.RecordMap.Demographic"/>
    <RecordReference name="PersonAlias"    required="0" repeating="1" recordMap="Pkg.POC.RecordMap.PersonAlias"/>
    <RecordReference name="PersonAddress"  required="0" repeating="1" recordMap="Pkg.POC.RecordMap.PersonAddress"/>
    <RecordReference name="PersonContact"  required="0" repeating="1" recordMap="Pkg.POC.RecordMap.PersonContact"/>
    <RecordReference name="PersonCoverage" required="0" repeating="1" recordMap="Pkg.POC.RecordMap.PersonCoverage"/>
    <RecordReference name="PersonProvider" required="0" repeating="1" recordMap="Pkg.POC.RecordMap.PersonProvider"/>
  </RecordSequence>

  <!-- Encounter group: one Encounter header, then N related sub-records. Repeats across the file. -->
  <RecordSequence name="Encounters" required="0" repeating="1">
    <RecordReference name="Encounter"         required="1" repeating="0" recordMap="Pkg.POC.RecordMap.Encounter"/>
    <RecordReference name="EncounterAlias"    required="0" repeating="1" recordMap="Pkg.POC.RecordMap.EncounterAlias"/>
    <RecordReference name="EncounterCoverage" required="0" repeating="1" recordMap="Pkg.POC.RecordMap.EncounterCoverage"/>
    <RecordReference name="EncounterLocation" required="0" repeating="1" recordMap="Pkg.POC.RecordMap.EncounterLocation"/>
    <RecordReference name="EncounterProvider" required="0" repeating="1" recordMap="Pkg.POC.RecordMap.EncounterProvider"/>
  </RecordSequence>

  <!-- Flat clinical entities at the top level: each can repeat without being inside a parent group. -->
  <RecordReference name="Allergy"          required="0" repeating="1" recordMap="Pkg.POC.RecordMap.Allergy"/>
  <RecordReference name="Social"           required="0" repeating="1" recordMap="Pkg.POC.RecordMap.Social"/>
  <RecordReference name="Diagnosis"        required="0" repeating="1" recordMap="Pkg.POC.RecordMap.Diagnosis"/>
  <RecordReference name="Lab"              required="0" repeating="1" recordMap="Pkg.POC.RecordMap.Lab"/>
  <RecordReference name="Vital"            required="0" repeating="1" recordMap="Pkg.POC.RecordMap.Vital"/>
  <RecordReference name="Problem"          required="0" repeating="1" recordMap="Pkg.POC.RecordMap.Problem"/>
  <RecordReference name="MedicalProcedure" required="0" repeating="1" recordMap="Pkg.POC.RecordMap.MedicalProcedure"/>
  <RecordReference name="Medication"       required="0" repeating="1" recordMap="Pkg.POC.RecordMap.Medication"/>
  <RecordReference name="Immunization"     required="0" repeating="1" recordMap="Pkg.POC.RecordMap.Immunization"/>

  <!-- Appointment group: one Appointment, then related sub-records. Repeats. -->
  <RecordSequence name="Appointments" required="0" repeating="1">
    <RecordReference name="Appointment"            required="1" repeating="0" recordMap="Pkg.POC.RecordMap.Appointment"/>
    <RecordReference name="AppointmentAction"      required="0" repeating="1" recordMap="Pkg.POC.RecordMap.AppointmentAction"/>
    <RecordReference name="AppointmentParticipant" required="0" repeating="1" recordMap="Pkg.POC.RecordMap.AppointmentParticipant"/>
    <RecordReference name="AppointmentSlot"        required="0" repeating="1" recordMap="Pkg.POC.RecordMap.AppointmentSlot"/>
  </RecordSequence>

  <!-- Survey group: one Questionnaire, then its Questions. Repeats. -->
  <RecordSequence name="Surveys" required="0" repeating="1">
    <RecordReference name="Questionnaire" required="1" repeating="0" recordMap="Pkg.POC.RecordMap.Questionnaire"/>
    <RecordReference name="Question"      required="0" repeating="1" recordMap="Pkg.POC.RecordMap.Question"/>
  </RecordSequence>
</ComplexBatch>
}

}
```

Design notes visible in this example:

- **Two styles mixed**: grouped (`<RecordSequence>` for patient-level and encounter-level clusters) and flat (top-level `<RecordReference repeating="1">` for clinical entities that don't need a parent record).
- **Required vs optional**: The top-level `Patient` sequence is `required="1"`; Demographics within it is `required="1"`. Everything else is optional.
- **No header or trailer**: The file's structure is fully expressible as body sequences.
- **Hybrid hierarchy rationale**: grouping Encounters and Appointments keeps the parent-child relationship explicit in the parsed object; keeping Allergies, Labs, etc. flat avoids an artificial parent layer that would complicate downstream DTLs.

## Common pitfalls

- **Batch class empty after generation**: usually a `targetClassname` / `BATCHCLASS` mismatch, or a referenced RecordMap missing `RecordInComplexMap = 1`.
- **Parser drops records**: referenced RecordMap is missing `LeadingData`, or the leading-data prefix in the file doesn't match exactly (case-sensitive, whitespace matters).
- **Generated helper-sequence class missing properties**: inner sequence had zero children, or children referenced a non-existent RecordMap.
- **Edits to the ComplexMap don't flow through**: you compiled but did not regenerate. The batch class reflects the state at last `Generate()` call, not the XData source.
- **Running `Generate()` on a hand-authored batch**: if `RECORDMAPGENERATED = 0`, the generator will not touch the batch class — this is a feature, but easy to forget if you later change it back to `1` and expect regeneration.
