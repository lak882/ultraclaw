## 1. Architecture: new `Inteclaw.*` stack replaces `InterClaw.Pipeline.*`

The chatbot at `/api/interclaw/production` now runs on a native IRIS pipeline
instead of shelling out to the `claude` CLI per turn.

| Layer | Before | After |
|---|---|---|
| Agent loop | `claude` subprocess per turn | `Inteclaw.BP.ChatProcess` (persistent BP) |
| Tool dispatch | Bash → Python script → Atelier HTTP → IRIS | `$ClassMethod(cls, "Execute", json)` in the same job |
| System prompt | 32k chars per turn (CLAUDE.md inlined) | ~2.5k short prompt + CLAUDE.md as first user message (cached) |
| Model call | Via `claude` process | Direct Bedrock Invoke / Invoke-with-response-stream |

**Performance comparison (ORU-to-ORU DTL task):**

| Pipeline | Wall | Input tokens | Output tokens | Tool calls | DTL compiled |
|---|---|---|---|---|---|
| Old InterClaw (Bash/Claude) | 116.4s | 472,302 | 6,223 | 21 | yes |
| Inteclaw typed tools | 61.4s | 159,209 | 4,152 | 10 | yes |
| Inteclaw3 (exec+spawn) | 119.8s | 267,759 | 6,659 | 16 | no (hit cap) |

### New classes

- `Inteclaw.REST.Dispatch` — `/chat`, `/events`, `/tools`, `/health`
- `Inteclaw.BS.ChatService` — inbound BS that routes ChatRequest to BP
- `Inteclaw.BP.ChatProcess` — agent loop: provider call, tool dispatch, event emission
- `Inteclaw.BP.EventWriter` — persists events to `^Inteclaw.ChatEvents`
- `Inteclaw.BO.ProviderOperation` — Bedrock/Anthropic HTTP + streaming SSE parser
- `Inteclaw.BO.ToolOperation` — tool dispatch boundary
- `Inteclaw.Session` — persistent conversation state
- `Inteclaw.Skill.Loader` — builds system prompt + bootstrap message
- `Inteclaw.Tools.*` — tool registry + 15 tool classes
- `InterClaw.V2.RESTAdapter` — translates frontend's `/api/start`, `/api/events`, `/api/approve` endpoints into Inteclaw's shape

### Namespaces deployed

| Namespace | Purpose |
|---|---|
| INTECLAW1 | Original typed-tools Inteclaw |
| INTECLAW3 | Added `exec` + `spawn_agent` for comparison |
| INTERCLAW | Production — frontend chatbot backend, dispatch swapped to `InterClaw.V2.RESTAdapter` |

Rollback: one-line `Security.Applications.Modify` to point dispatch back to
`InterClaw.Pipeline.REST.Dispatch`; old classes still installed.

## 2. Tool system

Typed tools discovered via `%Dictionary` scan of concrete subclasses of
`Inteclaw.Tools.Base`. Each has Name, Description, JSONSchema.

### Tools registered

| Tool | Purpose |
|---|---|
| `run_sql` | Typed SQL via `%SQL.Statement`; returns JSON rows |
| `list_docs` | List class/routine/include names |
| `get_doc` | Read a class source |
| `put_class` | Create/update a class via `$System.OBJ.LoadStream` |
| `compile_class` | Recompile a class |
| `get_schema` | Walk `^EnsHL7.Schema` for categories/messages/segments/fields |
| `test_dtl` | Invoke a DTL in-memory, return per-segment diff |
| `production_status` | Active production + host state |
| `list_skill_files` / `read_skill_file` | Skill repo filesystem access |
| `exec` | Run arbitrary Python with embedded `iris` module in scope |
| `spawn_agent` | Fork N parallel Claude sub-agents on their own bridges |
| `echo` | Debug round-trip |
| `enter_plan_mode` / `exit_plan_mode` | Session deny-list toggle for destructive tools |

### Plan mode + permissions

- `Inteclaw.Tools.Permissions` builds a deny-list context per session, read from `^Inteclaw.SessionPerm` globals
- `Inteclaw.Tools.Registry.DescriptorsJSON(permCtx)` filters blocked tools from the model's view
- `Inteclaw.Tools.Registry.Dispatch(..., permCtx)` refuses blocked invocations with a teaching message
- `enter_plan_mode` sets deny-list `put_class,compile_class,exec,spawn_agent,test_dtl`; only read tools stay available
- `exit_plan_mode` clears the global

**Cross-job state gotcha (saved to durable memory):** tried to persist
plan state on the `Inteclaw.Session` %Persistent class first. Didn't work —
the BP's enclosing Ensemble transaction doesn't see the BO job's committed
writes until it closes. Plain globals bypass transaction isolation entirely
and a `SET` in one job is visible to another immediately.

### Exec hard-refuses SQL

`Inteclaw.Tools.Exec.Execute` scans incoming code for `iris.sql.exec` or
`iris.sql.prepare`; if found, returns a refusal that points the model at
`run_sql`. Tool description also states the restriction so the model sees
it in the catalog and routes SQL correctly up-front.

## 3. Streaming + live UI

Bedrock's `invoke-with-response-stream` + AWS event-stream framing parser in
`Inteclaw.BO.ProviderOperation.StreamBedrock`. Events emitted live:

| Server event | What it is |
|---|---|
| `delta` | text_delta chunks (accumulated but not displayed in main bubble anymore) |
| `thinking` | thinking_delta chunks (live into thinking card) |
| `tool_use` | emitted at `content_block_stop` with full input JSON |
| `tool_result` | tool output |
| `reclassify_as_thinking` | fires at `content_block_start` for tool_use; preamble text → thinking card |
| `usage` | input/output/cache_read/cache_write tokens |
| `output` | terminal full-text; UI finalizes bubble via `animateText` |
| `done` | end-of-turn, sets `^Inteclaw.ChatEvents(bridge, "done")=1` synchronously |

### Final main-bubble text UX

- Delta handler accumulates `currentStreamText` but does NOT write to the DOM
- `output` event triggers `animateText` for character-level formatted-markdown reveal
- Tool_use and thinking cards still stream live

This is the Claude Code subprocess-era UX without the subprocess overhead.

### Reasoning steps UI

- Two independent auto-expand slots: one for thinking, one for tool. Latest
  of each stays visible simultaneously
- Adding a step of a given type collapses only the previous active card of
  that same type
- `output` collapses both slots' bodies but keeps step rows visible above
  the answer as history
- Tool cards preserve the input (SQL, Python, DTL source) in `content` and
  append the result below a `--- Result ---` separator when tool_result
  arrives

### Hang guards

- `Emit("done",...)` also writes `^Inteclaw.ChatEvents(bridge,"done")=1` synchronously so the bridge flag never lags behind the event
- `OnRequest` body wrapped in Try/Catch; uncaught exceptions emit error + done
- Stall detector in `/api/events` long-poll: 90s without progress emits `stream stalled` error + sets done

## 4. Caching + token accounting

`Inteclaw.Msg.ProviderResult` now has four token fields: InputTokens,
OutputTokens, CacheReadTokens, CacheWriteTokens.

`ProviderOperation` attaches `cache_control: {type: "ephemeral"}` to:
- System prompt (promoted to a typed text block)
- Last content block of the last user message

Anthropic's prompt cache:
- Bills cache_read at 10% of normal input rate
- Bills cache_creation at 125%
- Bills fresh input at 100%

### Per-model cost table (frontend)

```
opus:   input 15,   output 75,   cacheRead 1.5,   cacheWrite 18.75
sonnet: input  3,   output 15,   cacheRead 0.3,   cacheWrite  3.75
haiku:  input  0.8, output  4,   cacheRead 0.08,  cacheWrite  1.0
```

Display format: `duration · $cost · Xk tokens in · Yk tokens out`.
Counters zero per-turn via `startTimer`.

### Tool_result truncation

BP caps persisted `tool_result` content at 2000 chars with
`[truncated N chars for transcript]` marker so historical turns don't bloat
`MessagesJSON` and drive per-turn cache_write costs.

## 5. Bootstrap pattern

CLAUDE.md is injected once per session as a synthetic first user message
wrapped in `<operating-manual source='.claude/CLAUDE.md'>...</operating-manual>`
via `Inteclaw.Skill.Loader.BuildBootstrapMessage()`. A synthetic assistant
"ack" follows it. The real user prompt becomes the next user message.

Why: mirrors OpenClaw pattern. Anthropic caches the stable prefix; follow-up
turns hit cache_read at 10% instead of repaying full input rate.

System prompt stays small (~2.5k chars): identity, tool index, SQL guardrails,
communication style, workflow rules, portal URL format for link generation.

## 7. Slash commands (frontend)

### `/model opus|sonnet|haiku`
Updates `cc.currentModel` via `setSelectedModel`. Model is sent per-request
in every `/api/start` payload — no server-state update needed.

### `/effort low|medium|high|max`
Updates `cc.currentEffort`. Sent per-request; adapter forwards as Bedrock's
`output_config.effort` for adaptive extended thinking.

Both persist via sessionStorage so settings survive reloads.

## 8. Platform fix — iris_site.py / user-site shim

`pip uninstall intersystems-irispython` removed the user-site `iris/` package
that was shadowing IRIS's own embedded `iris` module. Without it, `iris.cls`
and `iris.gref` worked cleanly in every `[ Language = python ]` method. No
override file needed in `mgr/python/`.

Saved as durable memory so future sessions don't reinstall the shim.
